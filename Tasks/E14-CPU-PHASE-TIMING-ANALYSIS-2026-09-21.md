## Primary research, accessed 2026-09-21

- Unreal Engine 5.8 Timing Insights: https://dev.epicgames.com/documentation/unreal-engine/timing-insights-in-unreal-engine . Timing Insights exposes frame-by-frame data, separate CPU/GPU tracks, detailed per-thread event timelines, and spike inspection.
- Unreal Engine 5.8 Timing Panel: https://dev.epicgames.com/documentation/unreal-engine/using-the-timing-panel-in-unreal-insights-for-unreal-engine . CPU/GPU timing events are organized on tracks and selected time ranges can be aggregated.
- Unreal Engine 5.8 Timers and Counters: https://dev.epicgames.com/documentation/unreal-engine/using-the-timers-and-counters-tabs-in-unreal-insights-for-unreal-engine . Timer events can be exported with aggregate statistics for automated analysis.
- Unity 6.0 `ProfilerMarker`: https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Unity.Profiling.ProfilerMarker.html . Named markers instrument arbitrary code regions and feed CPU Profiler/Recorder data.
- Unity 6.0 CPU Usage Profiler: https://docs.unity3d.com/6000.0/Documentation/Manual/ProfilerCPU.html . Timeline/hierarchy views break selected frames down by thread/category and expose render/script/physics/animation timing.
- Unity 6.0 Profiler API: https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Profiling.Profiler.html . Profiling instrumentation affects performance and most runtime profiling APIs are intended for development builds.

Applicability: mature engines retain named timing events and can aggregate or export them, but Astral currently has only four flat Win32 main-thread phases. This packet adds fail-closed validation and descriptive statistics for those exact intervals. Public documentation only; no proprietary source copied and no dependency imported.

## Reproducible acceptance contract

`analyze_frame_phase_timing_capture.py` must accept only schema-1 CSV generated by the current `FramePhaseTimingCapture` contract:

- exact metadata for `main_thread_phase_wall_ms`, `std::chrono::steady_clock`, phase order, `cpu_scope=Win32_main_thread_only`, `gpu_timing=unavailable`, and `acceptance_claim=none`;
- exact six-column header and canonical non-negative six-decimal millisecond values;
- post-warmup, strictly contiguous frame indices;
- bounded `max_samples` and consistent saturation state;
- positive loop total for every measured row;
- `loop_total_ms` consistent with the four serialized phases within at most 3 microseconds, covering only independent six-decimal serialization rounding, not arbitrary data drift.

The analyzer computes min/mean/p50/p95/p99/max/sum for each phase and loop total plus aggregate phase shares. It must re-verify the existing production benchmark manifest, exact candidate commit and `AstralGame.exe` SHA-256, exactly one `cpu_phase_timing_csv` evidence role, file size/hash, safe relative path, and no symlink escape. Output is fresh/exclusive and all performance/parity/overhead/GPU/thread-attribution/independent-acceptance flags remain false.

The statistics are descriptive only. `render_submit_ms` remains main-thread GDI submission work, not GPU execution time. Aggregate phase share is not a CPU utilization percentage and must not be used to infer work occurring on other threads or the GPU.
