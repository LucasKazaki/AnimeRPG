# Package a Windows engine project

The reusable package command builds the Release editor, creator, headless player
and native player from one clean source revision. It stages the selected Content
directory unchanged, including glTF buffers/textures, scenes, prefabs, audio and
project notices. The native player loads Content/project.json beside its EXE.
Use a project generated by AstralProject or an equivalent supported project.

With installed VS2022 x64 tools and Python, run the following from the source
checkout, replacing the explicit paths. Keep the build path short: deeply nested
MSBuild compiler-probe paths can exceed Windows tool limits. Output must not
exist, its parent must exist, and each evidence directory must be new.

```powershell
python Scripts/package_engine_project.py `
  --source C:/AI/projects/astral-demo-candidate `
  --build C:/AI/astral-build/package-release `
  --content C:/AI/projects/MyProject/Content `
  --destination C:/AI/packages/MyProject `
  --evidence C:/AI/package-evidence/MyProject-first `
  --cmake '<installed CMake executable>' `
  --dumpbin '<installed MSVC x64 dumpbin executable>' --jobs 2
```

The command checks a clean source head/tree, actual Release builds, x64 PE
imports, content identities/hashes and output integrity. It requests the static
MSVC runtime and refuses unbundled dependencies outside its explicit Windows
system-DLL list. Additional notice files can be included with repeated
`--notice <file>` arguments. Available repository license/notice files are copied
automatically; project notices are retained with the rest of Content.

No existing output is overwritten. Internal links/reparse entries, hard links,
invalid Windows names and case collisions are rejected. Inputs must remain
stable while staging; the complete Content snapshot is checked again, including
new/removed files and directories. On failure, logs and any partial package are
preserved for inspection. This is an ordinary developer staging contract, not a
filesystem sandbox against a concurrent hostile writer.

Double-click AstralEnginePlayerWin32.exe in the completed package. For editing,
launch `AstralEditor.exe <absolute Content path> project.json`; the editor also
provides File > Open Project. START-HERE.txt gives the creator and headless
commands. BuildInfo.json records the exact source and PE imports, while
release-manifest.json seals the package bytes. The player currently uses CPU
rendering. The separate offscreen D3D11 pass does not imply GPU presentation.

Actual native launch from an unrelated working directory, scene behavior,
resize/restart/close, headless captures and clean-machine compatibility require
their own observed checks. A successful manifest does not establish those
results. Package acceptance and the demonstration rehearsal remain pending until
the QA receipt records them.
