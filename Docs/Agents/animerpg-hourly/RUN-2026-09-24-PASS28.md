## Implementation

`ShadowbladeLoadoutWorkbench` evaluates candidates on copies of the authoritative loadout, so previews and recommendations never spend parts, equip gear, overwrite presets, or otherwise mutate the live build. Recommendations iterate only the fixed existing module catalogue and use `TryEquipModule()` on copied state as the ownership/slot-compatibility gate. Five explicit build focuses use small deterministic original weights; ties resolve by stable module enum order.

CurrentSlot scope removes a family bonus newly activated by the candidate before scoring, so the player can judge direct slot contribution. WholeBuild scope scores the complete resulting `ShadowbladeLoadout::Profile()`, preserving the existing Cooling/Rift/Civic family rules.

Stateful preset metadata has one authority boundary. Labels and last-successful-preset state live with the authoritative `ShadowbladeLoadout`, so ordinary loadout assignment copies or clears them atomically with the saved presets and build. Label mutation remains private workbench behavior exposed through the paired `ShadowbladeActions` owner, and the public workbench accessor is const-only. Every successful preset application, including the pre-existing public `actions.Loadout().ApplyPreset(...)` path, records the applied slot inside the authoritative `ShadowbladeLoadout::ApplyPreset()` implementation, so recall bookkeeping cannot be bypassed by an established caller path. `ResetTransientStatePreservingLoadout()` preserves the loadout and timing preset, so encounter retry or training start retains the paired preset metadata.

Preset recall routes through the existing validated `ApplyPreset()` path and changes remembered selection only after a successful validation/application. Preset labels require an already-saved slot, trim outer ASCII spaces, preserve internal spaces, reject empty/over-24-byte/control-character values atomically, and clear without changing the saved preset or equipped build.

## Independent-review repairs so far

Independent Codex review found eight material issues before the next final-gate candidate:

1. `CurrentSlot` scoring accidentally included a family synergy activated by the candidate. The scoring path now removes that newly activated family bonus before focus scoring; `WholeBuild` retains it.
2. The initial implementation appeared before its bounded task/backlog/receipt records. The records were added and now define allowed paths, acceptance, verification and evidence boundaries.
3. A workbench obtained from one action owner could previously accept another owner's loadout for stateful label/preset metadata. Those mutators are private and exposed only through the paired `ShadowbladeActions` owner, with a cross-owner regression.
4. The existing transient reset rebuilt the whole `ShadowbladeActions` object and would have lost labels/last-applied metadata while preserving saved presets. The reset was repaired and a registered regression covers the exact failure mode.
5. Even after the owner wrappers, a public non-const `LoadoutWorkbench()` accessor still exposed implicit copy assignment, allowing metadata to be copied between owners. That accessor was removed; the only public workbench view is now const-only.
6. The existing public mutable `ShadowbladeActions::Loadout()` reference still allowed whole-loadout replacement to separate workbench metadata from the build it described. Preset labels and last-applied metadata were moved into `ShadowbladeLoadout`, and replacement regressions cover clearing and transfer in both directions.
7. The same mutable loadout accessor still exposed a direct `ApplyPreset()` path that could successfully change equipment without updating new recall bookkeeping. Successful recall bookkeeping now lives in authoritative `ShadowbladeLoadout::ApplyPreset()`, and a regression calls the direct path for two different slots to prove recall tracks both.
8. The retained run receipt omitted `Engine/Scene/ShadowbladeLoadout.h` even though the exact diff moved metadata there. This receipt now lists and describes that production path explicitly.

Earlier review threads were answered and resolved after their repairs. The two findings from the review of `df6d35783f3120ddeff06f1b78436809287736cf` are repaired in later commits and require fresh exact-head hosted gates plus fresh independent review before merge.
