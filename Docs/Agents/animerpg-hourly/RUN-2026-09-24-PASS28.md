## Implementation

`ShadowbladeLoadoutWorkbench` evaluates candidates on copies of the authoritative loadout, so previews and recommendations never spend parts, equip gear, overwrite presets, or otherwise mutate the live build. Recommendations iterate only the fixed existing module catalogue and use `TryEquipModule()` on copied state as the ownership/slot-compatibility gate. Five explicit build focuses use small deterministic original weights; ties resolve by stable module enum order.

CurrentSlot scope removes a family bonus newly activated by the candidate before scoring, so the player can judge direct slot contribution. WholeBuild scope scores the complete resulting `ShadowbladeLoadout::Profile()`, preserving the existing Cooling/Rift/Civic family rules.

Stateful preset metadata now has one authority boundary: `ApplyPreset`, reapply, label set, and label clear remain private workbench operations and are exposed through the paired `ShadowbladeActions` owner, so a caller cannot supply another action owner's loadout. `ResetTransientStatePreservingLoadout()` snapshots/restores the paired workbench beside the already-preserved loadout and timing preset, preventing encounter retry or training start from discarding labels/last-preset recall while saved presets survive.

Preset recall routes through the existing validated `ApplyPreset()` path and updates remembered selection only after success. Preset labels require an already-saved slot, trim outer ASCII spaces, preserve internal spaces, reject empty/over-24-byte/control-character values atomically, and clear without changing the saved preset or equipped build.
