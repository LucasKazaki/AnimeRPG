## Independent-review and CI repairs

Fresh Codex review on initial candidate `f8c5daf26504930b890279a83867fc79a7ab02aa` found two material P2 issues.

1. `LandmarkEncounter::Retry` rebuilt `ShadowbladeActions` from scratch, which would erase acquired/equipped items and saved presets. The repair adds `ResetTransientStatePreservingLoadout`, directly regression-tests persistent loadout survival plus transient reset behavior in the registered Shadowblade test target, and makes the production encounter retry call that helper. The existing dedicated `LandmarkEncounterTests` still exercises retry reset and timing-preset behavior.
2. The original legal-catalogue build never exceeded most action-tuning clamp thresholds, so loose upper-bound assertions did not prove the clamps existed. The repair exposes the pure profile-to-action transform, changes its clamp arithmetic to overflow-safe `std::clamp`, and directly exercises `INT_MAX` and `INT_MIN` profiles against exact cap/baseline outputs.

The initial candidate's Windows Debug/Release and release-manifest workflows passed but became stale after those repairs. A later repaired candidate `2c0c1aa35ec957058760817cf23a3976756858bc` then failed the Windows Debug build at link time because the pass-17 test directly called `LandmarkEncounter` from the `ThoughtCommandsTests` target, which does not link `LandmarkEncounter.cpp`. That failure was not bypassed and CMake was not changed. The test was corrected to exercise the persistent reset contract through linked `ShadowbladeActions`, while production `LandmarkEncounter::Retry` calls the tested helper and its existing dedicated test target continues to cover encounter retry semantics. Exact-final-head hosted verification is required again after this correction.
