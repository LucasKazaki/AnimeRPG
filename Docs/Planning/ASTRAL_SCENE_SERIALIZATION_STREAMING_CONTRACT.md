# Astral Engine — scene serialization and streaming effect contract

This is an internal engine contract generated by the Company Runtime native executor from the current source tree. It does not authorize gameplay, encounter, narrative, art, audio, public release, or UE5 import work.

## Contract boundary

- Canonical scene serialization remains deterministic: entity records are ordered by entity id and use the `ASTRAL_SCENE_V1` header.
- Deserialization must fail closed on malformed headers, missing or trailing records, non-canonical ordering, non-finite coordinates, oversized payloads, and entity counts above the bounded limit.
- Scene snapshots are data-only engine fixtures; they are not gameplay state or a network protocol.
- Streaming work must preserve the same canonical snapshot contract across load, unload, retry, and failure recovery.
- The next implementation packet must measure load/unload latency and RAM/VRAM impact using procedural fixtures before any asset or gameplay expansion.

## Current acceptance gate

The current canonical serialization and world-blockout tests must pass in the retained native build. A passing check establishes the serialization contract only; it does not prove streaming performance or 3D runtime acceptance.
